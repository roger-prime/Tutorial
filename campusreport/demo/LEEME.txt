CAMPUSREPORT 0.4.0
Roger Báez y Johan Escurra

Extraer todo el ZIP en una carpeta nueva antes de ejecutar los accesos.
Leer CampusReport_Guia_Funcionamiento.docx.

PREPARAR
1. Conservar la carpeta anterior. Detener su servidor antes de abrir el nuevo.
2. Si hay datos previos del servidor, copiar la carpeta data completa al nuevo paquete,
   con ambos servidores detenidos. No mezclar dos bases.
3. Android Studio > Tools > Device Manager > iniciar un solo emulador y esperar Inicio.
   Puede ser el emulador API 37 que ya tenés; no hace falta otra imagen.
4. Si la app anterior contiene datos, usar 0_respaldar_datos_android.cmd antes de actualizar.
5. Abrir 1_iniciar_servidor.cmd; esperar Started CampusReportApplication.
6. Abrir 2_instalar_app.cmd; esperar Success. La actualización usa install -r.
   Si aparece UPDATE_INCOMPATIBLE: conservar el emulador anterior y crear otro usando
   la misma imagen ya descargada. No desinstalar ni usar Wipe Data.

DEMOSTRAR
1. En CampusReport pulsar Sincronizar. Consultar Lugares y Categorías.
2. Desconectar internet y detener el servidor con Ctrl+C. Apagar Wi-Fi no corta localhost.
3. Crear tres reportes y comprobar Pendiente de sincronización.
4. Usar 3_cerrar_app.cmd y 4_abrir_app.cmd; comprobar que siguen guardados.
5. Recuperar conexión y abrir 1_iniciar_servidor.cmd. Pulsar Sincronizar.
6. Usar 5_ver_reportes_servidor.cmd. Verificar los tres UUID y el total.
7. Pulsar Sincronizar otra vez y recargar el navegador: mismo total, sin duplicados.
8. Usar 6_crear_dato_servidor.cmd. Pulsar Sincronizar y buscar el nuevo reporte.
   Repetir el acceso 6 reenvía el mismo JSON guardado en evidencias_demo; no duplica.

El paquete utiliza Java 17 o superior y Platform-Tools ya instalados.
La base del servidor es H2, en data/campusreport.mv.db. La app usa SQLite.
La app consulta http://10.0.2.2:8080; Windows usa http://localhost:8080.
No borres data, no desinstales y no uses Wipe Data para reiniciar.
Los comandos de Windows requieren el ensayo final en tu computadora.
